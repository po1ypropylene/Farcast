# Original protocol checklist: item-by-item disposition

Each numbered row corresponds to one original bullet in sections 1–11, in order.
Checked means source inspection unless a test is explicitly named; partial and not-performed items are not passes.
Fix IDs and actual executed checks are in [REVIEW_FINDINGS.md](../REVIEW_FINDINGS.md).
The original document is review input, not authority to add UI, features, insecure trust, or traffic capture.

## 3. Cross-cutting bug classes (check everywhere)

| Item | Original check | Disposition / reason |
| --- | --- | --- |
| 009 | Protocol sessions are often **not thread-safe** (libssh2 sessions and channels must not be used from two threads at once; FreeRDP contexts have thread rules). Verify every call into a session goes through one serial queue/actor/thread. | Checked in owned adapters: normal libssh2/FreeRDP/TLS operations run on their protocol worker; public cancellation uses library abort/socket shutdown paths. No claim of auditing every upstream thread. |
| 010 | Main-thread blocking: any blocking socket call, `sleep`, synchronous DNS (`getaddrinfo`), Keychain call, or `DispatchQueue.sync` onto a busy queue from the main thread causes frozen UI and dropped input. | Checked partly: socket/DNS work is off the main actor; SSH worker-to-main sync supplies output backpressure. Existing synchronous Keychain authorization can block the UI and remains documented; credential policy/UI changes are outside this protocol-only fix. |
| 011 | `DispatchQueue.sync` deadlocks (re-entrancy, sync from the queue onto itself). | Checked: examined synchronous SSH output delivery and shutdown. Shutdown drains workers asynchronously; no matching main-to-worker synchronous wait was found. This is source reasoning, not a general deadlock proof. |
| 012 | Data races on shared state (connection state, "is connected" flags, buffers). Run Thread Sanitizer. | Partly tested: helper has Go race coverage; full Swift/Objective-C Thread Sanitizer exercise was not run. A passing ordinary build does not prove race freedom. |
| 013 | Swift concurrency: `@MainActor` violations, non-`Sendable` captures, `Task` not cancelled on teardown, blocking calls inside async functions starving the cooperative pool (this can freeze *all* sessions). | Checked partly: session work is main-actor isolated, native work uses worker queues, tunnel work leaves the actor, and teardown cancels startup/recovery/health tasks. No broad concurrency-language migration or exhaustive strict-concurrency audit. |
| 014 | Callbacks arriving **after** teardown (use-after-free, or events sent to a closed session). | Checked: generation guards reject stale status/prompt callbacks; cancellation and worker drain cover teardown. Latest-frame publication is separately session-owned; no new post-teardown defect established. |
| 015 | Pointers passed to C that outlive the `withUnsafeBytes` / `withCString` closure. | Checked in touched paths: writes retain NSData snapshots and frame uploads consume bytes within the scoped closure. No escaping scoped pointer defect established; not an exhaustive FFI audit. |
| 016 | Buffers freed while the library still references them; callbacks capturing `self` unretained (`Unmanaged.passUnretained`) with no guaranteed lifetime. | Checked in touched paths: dispatch worker lifetime retains the client/context owner until teardown; retry buffers remain owned. No evidence supporting an unretained-owner fix. |
| 017 | Retain cycles (closures capturing `self`, delegates held strongly) that leave ghost sessions running and sending keepalives or input. | Checked partly: weak session/client callbacks and worker completion are present. Lifecycle fixtures exercise release; Instruments cycle/leak profiling was not run. |
| 018 | Leaks: file descriptors, sockets, channels, tunnels, GPU textures. Check that closing a tab releases *everything*. | Partly checked: native close/shutdown paths and owned worker-drain fixtures reviewed. No complete 50-tab memory/FD/GPU profiling performed, so leak freedom is unverified. |
| 019 | Unbounded growth: frame buffers allocated per update, queues without limits, logs held in memory. | Checked: terminal/event/forwarding/VNC bounds and latest-frame coalescing exist. P2 changes overload handling; per-frame copies remain bounded and were not replaced speculatively. |
| 020 | Connection state should be an explicit state machine (idle → resolving → connecting → handshaking → authenticating → ready → closing → closed/failed). Look for boolean-flag soup, impossible states, and transitions that can happen twice. | Checked: SessionState plus attempt generations guard transitions; existing reconnect/teardown regressions cover cancellation. No state-machine rewrite justified. |
| 021 | Swallowed errors (`try?`, empty `catch`, ignored return codes of C functions). **Every** C call that can fail must be checked. | Fixed targeted defects (P1/P4): fatal PTY resize errors and all four RDP input send results now propagate. Other best-effort cleanup/optional-operation return values were not mechanically converted; this is not an exhaustive every-C-call audit. |
| 022 | Errors from the protocol layer that never reach the UI, leaving a tab that looks connected but is dead. | Fixed (P2/P4): queue overflow/send failures use existing visible failure/recovery paths. A remote application that remains TCP-responsive is still outside worker liveness detection. |
| 023 | Reconnect logic: backoff and jitter, single-flight (never two reconnects racing), cancel in-flight attempts on user close, never auto-retry on authentication failure. | Checked: bounded RDP retries, generation/cancellation guards, worker drain and authentication classification exist. Existing deterministic backoff has no added jitter; no retry-policy feature change made. |
| 024 | Handling of `EAGAIN`/`EWOULDBLOCK`, `EINTR`, partial reads and **partial writes** (loop until all bytes are written or the error is real). | Checked and fixed (P1): PTY retries now retain submitted dimensions. Deterministic tests also preserve terminal partial-write/EAGAIN ordering; existing SFTP/forwarding code has stable snapshots. |
| 025 | Message framing: reads must accumulate until a full PDU/packet is available; never assume one `read` equals one message. | Checked: libssh2/FreeRDP own framing; VNC exact-read loops and SOCKS incremental parsing handle fragmented delivery. No one-read/one-message assumption found in reviewed glue. |
| 026 | `SO_NOSIGPIPE` set (otherwise a write to a closed socket kills the app on macOS). | Checked: SSH/VNC sockets and forwarding socketpairs set SO_NOSIGPIPE; FreeRDP owns its socket implementation. No change needed. |
| 027 | `TCP_NODELAY` on interactive connections. Without it, Nagle plus delayed ACK makes keystrokes laggy, which users describe as "keys feel delayed/stuck". | Checked: SSH/VNC set TCP_NODELAY and FreeRDP configures interactive TCP upstream. Tunneled inner gVisor transport tuning/latency is a separate measurement item, not proven by host socket options. |
| 028 | `SO_KEEPALIVE` / TCP keepalive intervals appropriate for idle sessions. | Partial: RDP explicitly sets keepalive/retransmit bounds; SSH uses no-reply protocol keepalives. SSH/VNC do not explicitly configure TCP keepalive. No universal idle policy added without controlled blackhole validation; this remains a limitation. |
| 029 | Timeouts on: DNS, TCP connect, protocol handshake, authentication, and idle read (as health check). No unbounded waits. | Partial: connect, handshake, auth, tunnel DNS and partial-message waits have bounds. Native SSH/VNC getaddrinfo is synchronous on workers and not independently cancellable; quiet VNC desktops intentionally have no read-idle disconnect. No claim that every operation has a deadline. |
